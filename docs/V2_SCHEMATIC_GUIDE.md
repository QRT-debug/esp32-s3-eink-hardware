**★ 实物核对（2026-10-11，用户翻看屏的 FPC）—— 推翻了此前"FPC 上不带电容"的推断**

- **8 个小电容**与 `ILI9341` 手册 **p.220** 电源元件表**完全对上**：`C11P/M`、`C12P/M`（飞跨电容 ×2 组）+ `C21P/M`、`C22M`（泵输出电容 ×2 组）= **8 颗 · 1 µF · 25 V · B 特性（X7R/X5R）** ⇒ **全部在屏模组内部，是屏厂的，我们不能动、也不需要动。**
- **2 个大电容**：最可能是 `VCI`（模拟）/`VDDI`（逻辑）供电的去耦 + 储能。
- ⇒ ★ **"模组自带" ≠ "板上不用加"**：模组内电容只能管**屏内部那一段**；**`3V3` → 主板走线 → `J6` 触点 → FPC** 这段引线的本地储能，只能主板自己给。所以 **`J6.9` 的 100 nF + 1 µF 照样加**（几分钱、面积可忽略）。
- ⇒ 副产品：这也解释了**"卖家转接板不焊电容也能跑"**（屏自带电容撑住了基础工作）；但同样说明它的板子**没为"主板 ↔ 屏这一段"做任何去耦** —— 试板高速下的不稳与此有关。
- ★ **顺带的 layout 要求**：`J6` 的 GND 脚（**1 / 8 / 19 / 20**）**每脚就近打地过孔到 L2** —— 屏内电荷泵的开关噪声回流要就近入地，不能靠绕远。

**⚠️ 为什么 LEDA 那颗不能放大电容（量化）**

PWM **关断**瞬间，电容经 `LED（5 颗并联）→ 3.3 Ω → Q3` 放电。回路阻抗 ≈ **3.3 + 2.2 = 5.5 Ω**（3.3 Ω = 限流电阻；2.2 Ω = 由实测 `63.5 → 75 mA` 反推出的 LED 并联动态电阻）。PWM 周期 @ 20 kHz = **50 µs**：

| 电容 | τ = 5.5 Ω × C | 对调光的影响 |
|---|---|---|
| **100 nF** | 0.55 µs | ✅ **无影响** |
| 1 µF | 5.5 µs | 🟡 最低亮度会略微抬亮 |
| **10 µF** | **55 µs > 整个 PWM 周期** | ❌ **LED 电流被平滑成准直流 ⇒ 调光基本失效**（关断期内仍有过半电流在流）|

⇒ **背光是"电阻限流 + 三极管斩波"，本来就不需要电源去耦。** 该做的是**把 LED 电流的回路走短**（`3V3 → J6.10 → … → Q3 → GND` 环路面积尽量小），而不是并电容。
（依据等级：回路阻抗由本板**实测**反推；`τ` 折算为**推算**。）

> ⇒ 主板的**显示区一共 5~6 个件**：`Q3` + 3 颗电阻 + **`J6.9` 那 2 颗去耦（必加）** + 可选 `J6.10` 1 颗（≤100 nF）（对外只有 `J6` 这一个连接器）。
> ★ **为什么卖家的转接板上看不到电容**：它是**被动转接板**（FPC → 2.54 排针），设计目标只是"把屏接出来"，**不负责去耦设计**；而且静态显示时屏电流只有几 mA，低速 + 短排线在实验室能扛过去 —— 这也正是试板"白底黑竖线"的部分来源（去耦不足 ⇒ 电源噪声串进信号）。

> ★ **先澄清一件事（2026-10-11 用户提问）**：这套**只是"背光"的开关 + 调光电路**，**不是"屏的驱动电路"** ——
> **屏本身不需要任何外部驱动电路**：`ILI9341V` 控制器**已经集成在屏模块里**，ESP32 只需给它 **SPI 6 根线 + 电源/地**。
> 所以 V2 的"显示部分"总共 = **6 根信号线 + 这 4 个背光件**。
> ★ 这套与**厂家转接板（32001）上的电路完全一致**（`V2_PLAN §4.4.1` 已一手核实两份厂家资料）：`S8050` + **1 k 基极串阻** + **10 k 基极下拉** + 限流电阻。**唯一差别是限流电阻的取值**（厂家 4.33 Ω ↔ 我们起始 3.3 Ω，见下）。
> ⚠️ **V2 是 `J6` 直连屏、没有转接板了** ⇒ **这套必须自己画在主板上**（试板上有它是转接板自带的）。

> ⚠️ **不能省掉三极管用 GPIO 直驱**：5 颗 LED 并联实测 **63.5 mA** > ESP32 单脚绝对最大 **40 mA**。
> PWM 频率取 **20 kHz**（本机带喇叭，1~5 kHz 会落进音频带）。

## 3. ★★ V2 的 IO 资源分配（从零规划 · 原则上避开特殊脚）

> **本版的硬原则**：**不用 strapping 脚做通用 IO**。
> （上一版把 I2C 放在 `45/46` 是错的 —— 那两个是 strapping 脚。已作废。）
>
> ★ **一个已确认的例外（2026-10-11）**：**`GPIO3` 用于 `U4.22 TXD`** —— 蓝牙 AT 回执接回 ESP32。理由：三个 strapping 里**只有它不影响"板子能否启动"**（详见 §3.8）。**`GPIO0` / `45` / `46` 仍然全部留空。**

### 3.1 先划清"哪些脚根本不能用 / 不该用"

| 类别 | 引脚 | 说明 |
|---|---|---|
| 电源 / 复位 | `3V3`(2) · `GND`(1,40,41) · `EN`(3) | EN 接复位按键 |
| **USB（固定）** | **`19` / `20`** | D- / D+，不可挪 |
| **UART0（固定）** | **`43` / `44`** | RXD0 / TXD0，下载口 |
| **★ 内部 PSRAM** | **`35` / `36` / `37`** | N16R8 的 Octal PSRAM 占用 —— **实测三脚网络为 `None`，完全不可用** |
| **★ strapping** | **`0` / `3` / `45` / `46`** | `0`=BOOT（只接按键）；**`3`=JTAG 源选择 → ★ 已用于 `U4.22 TXD`**（三个里唯一不影响启动的，见 §3.8）；`45`=VDD_SPI 电压选择；`46`=启动模式 + ROM 日志。**`45` / `46` 仍全部留空** |
| 模组未引出 | `22`~`34` | WROOM-1 不引出 |

**⇒ 可自由分配 = 26 个**：`1~18`(18) + `21`(1) + `38~42`(5) + `47`/`48`(2)

### 3.2 ★★ 唯一的硬瓶颈：ADC 只有 `GPIO1~10` 能用

**ESP32-S3 的 ADC2 与 WiFi 冲突** ⇒ 实际只有 **ADC1 = `GPIO1~10`**。

**而 V1 在这 10 个脚里已经用掉 9 个**：`1`/`2`(I2C) · `4`/`5`/`6`(编码器) · `7`(按键) · `8`(SD CS) · `9`/`10`(TFT DC/CS)，**只有 `3` 是空的**（而 `3` 是 strapping，本版不用）。

**⇒ 要放 3 路 ADC（VBUS / CC1 / CC2），必须从 `1~10` 里搬走 2 个功能。**

| **6** | **新增 1 根线：`U4.22 TXD` → `U1.9`**（模组脚 9 = `GPIO16`）| 原本只到 `J8.1` | **`GPIO16`**（并入 `BT_TXD` 网 —— 见 §3.8；★ 2026-10-11 由 `GPIO3` 改为 `GPIO16`）|

### 3.5 代价与注意

**① 代价：SD 卡的"插拔检测（CD）"被取消** —— 它的 `GPIO21` 让给了 SD 的 CS。
- 影响：系统无法自动感知"卡插入/拔出"，需软件轮询或手动刷新
- 若**必须保留 CD**，见 §3.6 的替代方案

**② `GPIO1` / `2` / `8` 做 ADC 输入，为什么没问题**
- 三者都是**普通 IO**，且都是 **ADC1 通道**（CH0 / CH1 / CH7）
- 它们不再做数字 IO，所以不存在负载冲突

**③ VBUS 检测必须分压**
- `VBUS` = 5 V，**超过 ADC 量程 3.3 V** ⇒ **分压 100 k / 33 k + 100 nF**（已定，`V2_PLAN §3.4`；5 V→1.24 V，12 V 误插→2.98 V 仍 < 3.3 V ✓）
- `CC1` / `CC2` 电压在 3.3 V 内（Type-C 的 Rd/Rp 分压约 0.4~1.3 V）⇒ **串 1 k 保护 + 100 nF 到 GND 直取**（已定，`V2_PLAN §3.4`）

**④ 背光 PWM 不能用 `GPIO4`** —— V1 的 `GPIO4` 是**编码器 A 相**。（测试板上用的是开发板空脚，两回事。）

**⑤ 电源指示灯不占 GPIO** —— 直接接 `5V_SYS` + 约 600 Ω，见 §2.4。

**⑥ ★★ `GPIO21` 的身份变了 —— 这是最容易漏的一步（2026-10-11 用户提问后查出）**
- **V1 的 `GPIO21` 是 `SD_MISO`**（`BOM.md`：`R12` 10 kΩ 上拉；`J2` 的 MISO 走它），**不是 SD 的 CS**。V1 的 SD CS 在 `GPIO8`（`R13` 上拉）。
- V2 把 **SD 的 CS 从 `GPIO8` 搬到 `GPIO21`** ⇒ **必须同时把 SD 的 MISO 从 `GPIO21` 挪到 `GPIO13`**（与 TFT 的 MISO **并成同一根**）。**漏掉这一步 ⇒ `GPIO21` 会一脚两用（既是 MISO 又是 CS），CS 一拉低就把回读线也拽低，SD 直接读不出来。**
- **为什么能并**：`GPIO13` 上两个从机（TFT 的 SDO 与 SD 的 DO）在 **CS 无效时都是高阻** ⇒ 这是**标准 SPI 多从机接法** ✓。
- **连带**：**`R12`（10 kΩ MISO 上拉）要跟着挪到 `GPIO13` 网**；`R13`（CS 上拉）跟着 CS 挪到 `GPIO21`。
- **一句话**：**CS 必须各自独立（`GPIO10` TFT / `GPIO21` SD），而 MISO 才是共用的那根（都是 `GPIO13`）。**

### 3.6 若必须保留 SD 插拔检测

> ⚠️ **2026-10-11 更新**：本节的「方案 B（CD 用 `GPIO3`）」**已作废** —— `GPIO3` 已分配给蓝牙 `U4.22 TXD`（见 §3.8）。**现在没有任何空闲脚**，只剩方案 A 一条路。

| 方案 | 做法 | 代价 |
|---|---|---|
| **A** | **SD 的 CS 与 CD 各占一脚**：`GPIO8` 给 CD 或 CS，另一脚从 `GPIO15/17/18` 里挪 —— 但那样**背光就没有干净脚了** | 需要把背光挪到 strapping 脚 ⇒ 违背原则 |
| ~~**B**~~ | ~~CD 改用 `GPIO3`~~ | ❌ **作废**（`GPIO3` 已给**频谱取样**）|

**⇒ 结论：直接取消 SD 插拔检测。** 它属于"nice to have"，而现在**余量真的是 0**（连 `GPIO3` 都用掉了）—— 不值得为它再去动 `45` / `46`。

> ★ **2026-10-11 用户确认「肯定要蓝牙」** ⇒ `U4` 与 `U15` **都保留**，**`GPIO39` / `40` / `42` 三个脚全部锁定、不可动用**（下表前两行**作废**，仅存历史）。

| PCM5102A 若不用 SCK | 最多 1 个 | ⚠️ 仍可选，但代价大（牺牲 I2S 的 BCK）|

**★ 为什么 `U4` 不是"可选项"，而是硬约束**

**ESP32-S3 只有 BLE 5.0，没有经典蓝牙（BR/EDR）。** 官方文档原文：

> 「**ESP32-S3 的 ESP-Bluedroid 仅支持低功耗蓝牙，不支持经典蓝牙。**」（ESP-IDF v5.4 蓝牙概述）

而蓝牙音频（**A2DP** / SBC 编解码）属于**经典蓝牙** profile ⇒ **ESP32-S3 自身根本放不了蓝牙音乐**，**必须外挂带 BR/EDR 的模组** —— 这正是 V1 要加 `U4`（亿佰特 EWM104-BT60SP3，BT5.2 **双模**）的原因。

⇒ 本工程里「要蓝牙音乐」与「保留 `U4`」是同一件事，**没有第二条路**（换 ESP32 经典款不在考虑内：本板已按 S3 的 USB/PSRAM 定架构）。

**★ 连带：本组 8 个脚（`GPIO38~42` / `47` / `48`）的最终占用**

| GPIO | 占用者 | 可动否 |
|---|---|---|
| `38` | PCM5102A（`U14.14`）| ❌ |
| `39` | 模拟开关 `U15` | ❌（要蓝牙就留）|
| `40` | **蓝牙 `U4.19` LED_A** | ❌ |
| `41` | 功放使能 `U16.1`（`R26`）| ❌ |
| `42` | **蓝牙 `U4.21` RXD** | ❌ |
| `47` / `48` | PCM5102A（`U14.13` / `U14.15`）| ❌ |

⇒ **音频/蓝牙这一组 6 个 GPIO 全部用满，一个都拿不回来。**

### 3.8 ★ 已定（2026-10-11）：`U4.22 TXD` 接回 ESP32 —— 落点 **`GPIO16`**（原定 `GPIO3`）

**现状（活体网表实测）**：`U4.22 TXD` → 网络 `BT_TXD` → **`J8.1`**（`J8` = 1×2P 2.54mm **DNP 调试排针**，`J8.2` = GND）。**它没有接到 ESP32。**

| 方向 | 通吗 |
|---|---|
| ESP32 → `U4`（发 AT 命令）| ✅ 通（`GPIO42` → `U4.21 RXD`）|
| `U4` → ESP32（AT 回执）| ❌ **不通**（只到 J8）|

**⇒ 接之前的后果**：固件**收不到 AT 回执** ⇒ 做不了"查询类"操作（读模块当前音量、读连接状态文本），只能靠 `LED_A`（`GPIO40`）那一个状态位。

---

**★ 用户决定：接回（2026-10-11）** ⇒ 网络名统一为 `BT_TXD`，与 `U4.22`、`J8.1` 合并为同一网络。

**★ 落点最终定为 `GPIO16`（2026-10-11 二次决策；原定 `GPIO3`）** —— 因为 `GPIO3`（`ADC1_CH2`）要腾给**频谱模拟取样**（§3.10.3 ⑬ **方案 E**）；为此**删掉用户键 2 `SW4`**（它原本占 `GPIO16`）。**UART1 RX 走 GPIO 矩阵 ⇒ 落到哪一个脚都行**，`GPIO16` 同样满足 §3.1 的全部约束（非 strapping、上电无特殊；仅"兼 `XTAL_32K_N`"，而我们不接 32 kHz 晶振）。

**为什么当初在 `3` / `45` / `46` 里挑的是 `GPIO3`**（U1 共 41 脚逐个核过，**当时**除这 3 个外没有任何空闲脚）—— ★ **下表仅存历史：最终落点是 `GPIO16`，它根本不是 strapping，论证比 `GPIO3` 更强**：

| 脚 | strapping 作用 | 上电被拉低的后果 | 可用？ |
|---|---|---|---|
| **`GPIO3`** | **JTAG 信号源**（高 = 引脚 JTAG / 低 = USB-JTAG）| **无** —— 两种取值都正常启动 | ✅ **选它** |
| `GPIO45` | **VDD_SPI 电压**（低 = 1.8 V / 高 = 3.3 V）| ❌ Flash/PSRAM 电压错 ⇒ **板子起不来** | ❌ |
| `GPIO46` | **启动模式**（配合 `GPIO0`）+ ROM 日志 | ❌ **可能进下载模式** | ❌ |

> ⚠️ **关键**：`U4` 的 TXD 在**上电瞬间的电平不能保证**（`U4` 与 ESP32 走同一路 3V3 上电，模组复位期间输出状态不定）⇒ `45` / `46` 的风险是**实打实的**；而 `GPIO3` 完全不受影响。

**代价 ≈ 0（2026-10-11 核验后更正）**：查实 —— **`GPIO3` 只有在烧写了 `EFUSE_STRAP_JTAG_SEL` 之后才参与"JTAG 信号源选择"**；**默认（未烧 eFuse）时 JTAG 固定走 USB**，`GPIO3` 的电平**不影响任何功能**。

- **不受影响**：启动 ✅ · USB 烧录 ✅ · **USB-JTAG 调试 ✅** · `GPIO39~42` 当普通 IO ✅（默认 eFuse 下**四者全不受影响**）
- ⚠️ 仅当你**将来烧 `EFUSE_STRAP_JTAG_SEL`** 时，`GPIO3`（被 TXD 驱动为常高）才会把 JTAG 源切到引脚侧 ⇒ 届时应改用 `EFUSE_DIS_PAD_JTAG` 固定回 USB（详见 §3.10 风险 ⑤）

**固件侧**：蓝牙 AT 走 **UART1**（UART0 留给 `GPIO43/44` 兜底排针）⇒ `UART1.TX` → `GPIO42`，`UART1.RX` → `GPIO3`。

**`J8` 保留**（DNP 不焊）：它与 TXD 同网 ⇒ 插 USB-TTL 可旁听；USB-TTL 的 RX 是输入 ⇒ **不会与 `U4` 的输出打架**。

> 注：`J8` 是 DNP ⇒ **不焊就是两个测试点**，不影响功能；需要调试时插 USB-TTL 监听。

### 3.9 ⚠️ 「WiFi + 蓝牙」两个 2.4 GHz 射频同板的新问题（V2 才有）

**本版新增 WiFi（天气界面）+ 保留蓝牙（`U4`）⇒ 板上有两个独立的 2.4 GHz 射频。**

| | 射频在哪 | 能否时间协调 |
|---|---|---|
| **WiFi** | ESP32-S3 `U1` **内置**（板载天线）| —— |
| **蓝牙** | `U4` **外部独立芯片**（模块自带天线）| ❌ **无法** |

★ 关键：ESP32-S3 有「**Internal co-existence mechanism between Wi-Fi and Bluetooth to share the same antenna**」（数据手册原文）—— 但那是**同一个芯片内部**的 WiFi/BLE 分时协调。**`U4` 是外部芯片，ESP32-S3 管不到它** ⇒ 两个 2.4 G 射频**只能靠物理隔离**，无法分时避让。

**实际影响评估（可接受）**：
- 天气是 **每 10 分钟刷一次**、每次几秒；蓝牙音乐是持续的 ⇒ **冲突窗口很小**
- 表现可能是"刷天气那几秒，蓝牙音乐卡一下"（若确实发生）

**⇒ 布局动作**：
1. **`U1` 与 `U4` 两处天线尽量拉开、且都朝板缘**（V1 已有"天线净空区"要求，V2 沿用）
2. **两者的天线净空区内侧都不要走线、不要放铜**（含 `L2`/`L3` 内层 —— 见 `V2_PLAN §10.6.4`）
3. 若实测干扰明显，退路 = 天气改为**手动触发刷新**（而非定时）

#### 3.10.3 ⚠️ 风险清单

**A 档 · 必须有对策**

**① `GPIO39` 的上电电平 —— ★ 纸面已判定安全（2026-10-11 补算，**不再是"待实测"**）**
- 背景：`GPIO39` 是 JTAG 的 `MTCK`，同时驱动 `U15` 的选通；V1 在它上面挂了 **`R25` = 10 kΩ 下拉到 GND**（网表核实）。原先的担心 = 「内部上拉 × `R25` 分压 ⇒ `U15` 选通状态不确定」。
- ★ **一手口径（2026-10-11 补，Espressif《ESP32-S3 Hardware Design Guidelines》Table 9「IO Pin Default Configuration」）**：`MTCK`(GPIO39) / `MTDO`(GPIO40) / `MTDI`(GPIO41) / `MTMS`(GPIO42) 的**复位态都只标 `IE`（输入使能），没有内部上拉** ⇒ **"内上拉 vs `R25` 拔河"这个前提本身就存疑**。另有社区观察称"`GPIO39` 上电会被上拉"（**来源不明**，可能只出现在下载模式或上电初段）。★ **按这个最坏情况也算过了（2026-10-11）**：
  - `R_PU`（内部弱上拉）= **45 kΩ（典型值）** ← **ESP32-S3-WROOM-1 数据手册 Table 10「DC Characteristics」**（原文 `R_PU … — 45 — kΩ`，**只给典型、未给最小/最大**）
  - `R25` = 10 kΩ 下拉 ⇒ `GPIO39` = 3.3 × 10/(10+45) = **0.60 V**

**⑪ SD 与 TFT 共享 SPI**（`GPIO11`/`12` 上挂着 `J2.3` / `J2.5`）⇒ **★ 共享的是 `MOSI`(`11`) / `SCK`(`12`) / `MISO`(`13`)，而 `CS` 必须各自独立**（`GPIO10` = TFT、`GPIO21` = SD —— **共用 CS 会让两个从机同时被选中、在 MISO 上对撞**）；**layout 注意 `GPIO11`/`12`/`13` 这三根的负载拓扑**（`J2` 支路要短）。
- ★ **对刷屏速度的影响（2026-10-11 补）**：**不会"严重"，前提是不在刷屏期间读 SD** —— SPI 分时独占，屏刷新的带宽本身不受 SD 影响（`ILI9341` 自带 GRAM，静态画面完全不占总线）；**影响只来自争用**：一次 FATFS 读是完整事务，期间总线被占，LVGL 的 `flush` 只能排队。粗算（40 MHz）：一屏 153.6 KB ≈ 31 ms，读同样大小的一张图也 ≈ 31 ms+ ⇒ **每帧读 SD = 帧率腰斩；只在开机/换图时读一次 = 无感**。
- **落地**：SD 只做**粗粒度访问**（一次性读进 PSRAM 再释放总线）；**别在 LVGL 的 `flush` / timer 路径里碰 SD**；两个设备各自 `spi_bus_add_device()` 注册（不同 CS、各自 `clock_speed_hz`），由 IDF 仲裁。
- ★ **"从 SD 放音乐 + 同时刷屏"会不会卡（2026-10-11 追加）**：**不会卡** —— 音频数据走 **I2S（`GPIO38`/`47`/`48`）**，与 SPI2 **不是同一根线**、不争带宽；SD 只负责"取压缩音频文件"，**128 kbps = 16 KB/s、320 kbps = 40 KB/s**，相对 40 MHz SPI（≈ 5 MB/s）**占用 ≈ 1%，可忽略**。真正要防的是三条：
  1. **SD 卡的偶发长延迟**（卡内部垃圾回收 / 磨损均衡，可达上百 ms）⇒ **音频环形缓冲 ≥ 200 ms**；
  2. **解码抢核** ⇒ MP3 解码任务 pin 到 **core 1**，LVGL 留 **core 0**；
  3. **播放期间别写 flash / 提交 NVS**（写 flash 会短暂关 cache，是最大的一次抖动源）。
  **音频 DMA 缓冲放内部 SRAM，不要放 PSRAM。**

**⑫ VBUS 5 V 超 ADC 量程**（3.3 V）⇒ **必须分压**（建议 100 k / 100 k）。
- ⚠️ **待核（2026-10-11 补）**：`100 k/100 k` 分压后**源阻抗 ≈ 50 kΩ**，对 SAR ADC 偏高 ⇒ **阻值需按 Espressif ADC 手册的"源阻抗 / 采样时间"要求核定**；稳妥做法 = 降阻值（如 `10 k/10 k` ⇒ 源阻抗 5 kΩ）**或**在 ADC 脚并 **0.1 µF** 到 GND。**本项为推断，尚未查实手册的具体限值。**

**⑭ ★★★（2026-10-11 核实功能时查出 · **A 档 · 必须改**）`U15` 的供电**绝不能**跟着 `U16` 一起搬到 5 V**
- **事实**：`U15`（TS5A23157）的 `V+` = **pin 8**（官方脚序，`SCHEMATIC_CHECKLIST:521`），V1 上它挂 **`VBAT`（电池 3.0~4.2 V）**。
- **V2 计划把它跟 `U16` 一起改到 `5V_SYS`**（`V2_DELETE_LIST §5.2`）—— **这是错的**。
- **判据**：`TS5A23157` 的逻辑输入阈值 = **`V_IH` = `V+` × 0.7**（TI 手册 §6.6）⇒

| 供电 | `V_IH` 门槛 | ESP32 输出 3.3 V 够吗 |
|---|---|---|
| V1 的 `VBAT`（4.2 V）| 2.94 V | ✅ 刚好够 |
| **若接 `5V_SYS`（5 V）** | **3.5 V** | ❌ **3.3 V < 3.5 V ⇒ 高电平不被保证 ⇒ `U15` 选通可能失效** |

- **一手佐证**：TI 官方论坛对**同一个问题**（`VCC` = 5 V、`IN1`/`IN2` 由 3.3 V 驱动）的答复原文：*"The VIH is 0.7 × VCC and at 5 V that is **3.5 V minimum** for a logic high… **A voltage signal of 3.3 V will not guarantee proper operation.**"*
- **★ 修复（一句话）**：**`U15.8`（`V+`）改接 `3V3_AUDIO`，不要接 `5V_SYS`。**
  - ⇒ `V_IH` = 0.7 × 3.3 = **2.31 V** ≤ 3.3 V ✅ 满足
  - ⇒ 代价：`Ron` 从（5 V 时 ~10 Ω）升到（3.3 V 时 **≤18 Ω**）—— 对 10 kΩ 级负载**无影响**
  - ⇒ 附带好处：**`U15` 与 `U17` 同域**，模拟信号范围 `0~3.3 V` 天然落在 `V+` 内 ✅
- **为什么原来没发现**：V1 用 `VBAT`（≤4.2 V）刚好压线通过；V2 改名 `5V_SYS` 时**只核了"网络名"，没重审"3.3 V 逻辑能不能驱动 5 V 域的开关"**。★ **通用教训：把一个器件从低轨搬到高轨时，必须重新核它的"逻辑输入阈值"。**
- **顺带自洽性检查**：`V2_PLAN §3.1` 原文写的就是"**5V 轨的两个用途**：给功放 + 给音频 LDO" ⇒ **本来就没打算给 `U15`** ⇒ `V2_DELETE_LIST §5.2` 那行是抄 V1 时的手滑。✅

#### 3.10.4 ★★ 怎么查"某个脚能不能做某个外设"（两张表，缺一不可）

**核心概念：ESP32-S3 的引脚功能分两层。** 只看一层，必然得出错误结论。

| 层 | 是什么 | 去哪查 | 回答什么问题 |
|---|---|---|---|
| **① IO_MUX**（固定功能）| 每个脚**硬件直连**的那几路外设 | **数据手册** Table 3-1「Pin Definitions」；SDK 里是 `components/soc/esp32s3/register/soc/io_mux_reg.h`（看 `FUNC_GPIOxx_*`）| 「这个脚**原生**是什么？」|
| **② GPIO Matrix**（交换矩阵）| 外设信号**可路由到任意脚** | **技术参考手册** 第 6 章「IO MUX and GPIO Matrix」的 Table 6-1（输入）/ 6-2（输出）；SDK 里是 `components/soc/esp32s3/include/soc/gpio_sig_map.h`（看 `xxx_IN_IDX` / `xxx_OUT_IDX`）| 「这个外设**能不能**接到某个脚？」|

**★ 决定性判据（哪些能过矩阵）**

| 外设类别 | 能否过 GPIO Matrix | 引脚自由度 |
|---|---|---|
| **UART · I2C · I2S · SPI2/3 · LEDC · TWAI · RMT · 脉冲计数** | ✅ **能** | **几乎任意 GPIO** |
| **ADC · 触摸** | ❌ **不能** | **只能用它自己的固定通道脚**：`ADC1` = `GPIO1~10`、`ADC2` = `GPIO11~20` |
| **USB** | ❌ 不能 | **固定 `GPIO19` / `20`** |
| **SPI0/1（Flash / PSRAM）** | ❌ 不能 | 模组内部 |

**★ 落到本板的四个实例**

| 用法 | 归类 | 依据 |
|---|---|---|
| **`GPIO3` → UART1 RX** | **矩阵** | IO_MUX 表里 `FUNC_GPIO3_*` 只有 GPIO（**所以你找不到 UART**）；但 `gpio_sig_map.h` 有 **`U1RXD_IN_IDX = 15`** ⇒ 靠矩阵接过去 |
| **`GPIO15` → LEDC** | **矩阵** | LEDC 属可路由外设 |
| **`GPIO1` / `2` / `8` → ADC** | ★ **必须靠 IO_MUX（不能过矩阵）** | ⇒ 这三个脚**必须恰好是 ADC1 通道**，它们正是 CH0 / CH1 / CH7。**这也正是"为放 3 路 ADC 而必须搬走 2 个功能"的根本原因** |
| **`GPIO9~14` → SPI** | **IO_MUX 原生** | `FSPICLK` / `FSPIQ` / `FSPID` / `FSPICS0` ⇒ **额外好处：不受"矩阵路由 SPI 只能 80 MHz"的限制** |

**★ 一句话记住**：**"表里没写" ≠ "不能用"** —— 先看它是不是"可过矩阵的外设"（UART / I2C / I2S / SPI2 / LEDC…），是的话**任意脚都能用**；**只有 ADC / 触摸 / USB 必须用它的固定脚**。

**★ 在 ESP-IDF 里怎么落地**

| 外设 | 写法 | 谁在配矩阵 |
|---|---|---|
| UART | `uart_set_pin(UART_NUM_1, tx, rx, rts, cts)` | 函数内部 |
| I2C | 建总线时传 `sda_io_num` / `scl_io_num`（或 `i2c_set_pin()`）| 驱动内部 |
| LEDC | `ledc_channel_config()` 里的 `gpio_num` | 驱动内部 |
| I2S | `i2s_std_gpio_config_t` 里逐脚指定 | 驱动内部 |
| **ADC** | `adc_oneshot_chan_cfg()` 里给的是**通道号**（`ADC_CHANNEL_n`），**不是 GPIO 号** | ❌ **无矩阵可走** |

**★★ 频谱流畅度估算（2026-10-11 · 纸面估算，未实测）**

> **★ 一句话版（白话）**：**够顺，30 帧/秒没问题。** 卡不卡跟"算 FFT"无关（那很快），只看两件事 —— **① 要攒够一段声音才能算一次**（512 点 ≈ 26 ms ⇒ 最多 39 帧/秒）；**② 往屏上画一次要多久**（只画频谱那一小块 ≈ 8 ms）。这两件事能同时进行 ⇒ 实际每帧 8~15 ms，**理论能到 60 帧以上，保守取 30 帧**。**要照做的三条：采样用连续模式（DMA）· 只重画频谱那一小块 · 解码和画频谱分到两个核。**

> **结论：目标 30 fps 是现实的；优化到位后 40~50 fps 可期。★ 瓶颈不是 FFT（很便宜），而是"采样窗长度 + 局部刷屏带宽"。**

**每帧时间预算（取 `N` = 512 @ `f_s` = 20 kHz）**

| 环节 | 时间 | 性质 |
|---|---|---|
| 采样窗填满（`N`/`f_s`）| **25.6 ms** | **硬下限** ⇒ 单帧最高 ≈ **39 fps** |
| 加窗 + FFT(512) | ~0.5~2 ms | 很便宜（ESP-DSP 有优化汇编）|
| 频段归并 + 对数映射（24~32 柱）| ~0.2 ms | 可忽略 |
| LVGL 局部重绘 + 刷屏（240×80×2 B = 38.4 KB @40 MHz）| **≈7.7 ms** | 与采样可重叠 |
| **流水后每帧**（DMA 常驻采样 + 处理/刷屏与下一窗重叠）| **≈ 8~15 ms ⇒ 上限 65~120 fps** | 前提 = 连续 DMA 采样 |

⇒ **实际落地取 30 fps**（给 MP3 解码和 WiFi 留余量）。

**三个决定性的做法**

1. **必须用 ADC 连续模式（`adc_continuous` + DMA）** —— 不要 oneshot 轮询：后者每点几十 µs，512 点就 20~50 ms，帧率掉到 20 fps 且占满 CPU。
2. **必须局部刷屏**（LVGL 9 默认只重画脏区）：全屏 153.6 KB 要 31 ms/帧（⇒ 上限 32 fps），而频谱区只要 38.4 KB（⇒ 7.7 ms）。
3. **双核分工**：MP3 解码 pin `core 1`；FFT + LVGL 留 `core 0`。

**参数建议**：`f_s` = **20 kHz**（覆盖到 10 kHz，音乐主能量都在这里）· **`N` = 512**（分辨率 39 Hz）· **24~32 根柱子**（对数频段）· **帧间 EMA 平滑 α ≈ 0.3**（20~30 fps 看起来也"顺"）。

**⚠️ 两条诚实的边界**

- 以上**全是纸面估算，未实测** —— 试板只跑过 LVGL 静态界面，**没跑过 ADC 连续采样 + FFT**。
- **模拟取样精度一般**（`§5.16`：ADC 有效约 8~10 bit）⇒ 柱高够用，别指望精密。★ **可选优化**：本地 / SD 播放时其实可以**直接对解码后的 PCM 做数字域 FFT**（更精确、零 ADC 占用）；代价是代码要分两条路径（蓝牙走模拟、本地走数字）。**当前统一走模拟，是为了"一套代码 + 蓝牙也能显示"。**
- **★ 为什么必须加缓冲**：`U15` 输出节点的等效源阻抗 = 求和电阻的并联值（**改增益后 ≈ 23.5 kΩ**）⇒ 直接并 ADC 的 100 nF 会严重分压、且 ADC 采样抽电荷会**扰动音源** ⇒ 必须缓冲。
- **ADC 侧幅度目标**：`V_BIAS` 1.65 V ± **0.8 V** ⇒ **0.85 ~ 2.45 V**，落在 ESP32-S3 ADC（11 dB 档）有效量程内 ✓。**实际摆幅随源幅度变 ⇒ 实物上按实测调（先 1:1 起，超了再在运放前加分压）。**
- **不占 IO 核对**：供电走 `3V3_AUDIO`；`U17A` 输出只到 3.5 mm 座；`U17B` 输出只到 `GPIO3`（**`GPIO3` 本来就是频谱的脚**）⇒ **净增 IO = 0** ✅

**★ 2026-10-14 复核：`line-out` 保留（不删）** —— 删除评估：只省 `R32`/`R33`/`C61`/`C62` + 3.5 mm 座（**`U17` 不可省** —— 频谱必须缓冲，`U15` 输出源阻抗 ≈23.5 kΩ）⇒ 5 件、≤¥2 的收益不值当。保留成本 **≈ ¥2~3**（座价已查：¥0.4~1.4）。用户拍板：**保留**。

  - ★★ **"插入即静音"开关的位置：串在喇叭回路**（`U16.VoP`($1N470) 或 `U16.VoN`($1N469) → 开关 → `J7`，任选一根；断开 BTL 回路 = 真静音）。**绝不能接 `AMP_INP`/`AMP_INN`**——它们同时是 line-out/频谱的取样网，碰了会把 line-out 一起静音（这正是"开关必须在取样点之后"的实质）。建议两段新网名：`SPK_A`（U16 侧）/ `SPK_B`（J7 侧）。
  - 座选型要点：**开关触点须与 Tip/Ring 音频触点相互独立**（画脚位时对照 datasheet）；现货候选 **`PJ-3582-B`**（星坤黑，5 脚 3 级立式带开关，现货 4395，¥0.84）· `PJ-3583-B`（¥0.77）——**直插件**（板上高度 15 mm，按外壳定）。
