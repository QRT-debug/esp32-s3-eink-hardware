## 1. ★★ 实测硬件数据（背光 —— V2 电路要用这些数）

### 1.1 转接板电路（用户实物）

转接板 = **1 个三极管 + 3 个电阻 + FPC 底座 + 引出排针**（即背光驱动小板）。
拓扑：`3V3 → R6(4.33 Ω) → LEDA → 5 颗 LED 串联 → LEDK → Q1(S8050, 低边) → GND`，
`GPIO4 → 1K → Q1 基极`。

### 1.2 ★ 实测参数（**关键，V2 背光取值直接照抄**）

| 量 | 实测值 | 怎么测的 |
|---|---|---|
| 背光 LED 正向压降 `Vf` | **2.935 V** | 点亮后量 LEDA-LEDK |
| 背光电流 `I` | **63.5 mA** | `V_R6 = 0.275 V ÷ 4.33 Ω` |
| 3V3 轨余量 | **0.365 V** | `3.3 - 2.935` |
| 电流回路阻抗 | **≈ 5.5 Ω** | 由 `ΔV/ΔI` 估 |
| PWM 周期 | **50 µs** | 20 kHz |

### 1.3 ★ 由此得出的两条硬结论

**① 背光不需要 LDO、不需要抬轨 —— 3V3 轨 + 一个电阻就够。**
余量 0.365 V 对一个 63.5 mA 的负载，只要 R6 取值合适就稳定。

**② V2 背光限流电阻取值：起始 3.3 Ω（≈75 mA）+ 可更换焊盘（4.3 / 2.2 / 1.5 / 1 Ω）。**
（V2_PLAN §4.4.4 已记录此方案，本文提供实测出处。）

### 1.4 ★★ 背光调光只能走 PWM —— 且**绝不能去掉开关管用 GPIO 直驱 LED**

- **PWM 是唯一可行方案**：余量 0.365 V 不够做模拟调光（线性区太窄）。
- ⚠️ **绝不能去掉 Q1 用 GPIO 直驱**：5 颗并联共 **63.5 mA**，而 ESP32 单脚
  **绝对最大 40 mA** ⇒ 会烧脚。
- **PWM 频率取 20 kHz**：本机带喇叭，1~5 kHz 会被人耳听到（线圈啸叫）。

### 1.5 ★★★ 跨项目铁律：给"被斩波的负载"并电容前，先算 `τ` 与开关周期的比值

**这条是踩坑得来的，务必记住：**

- 背光 = 电阻限流 + 三极管斩波（20 kHz ⇒ 周期 **50 µs**，回路阻抗 ≈ **5.5 Ω**）
- **若在此处并 10 µF**：`τ = 5.5 Ω × 10 µF = 55 µs` **> 整个开关周期** ⇒
  电流被平滑成准直流 ⇒ **PWM 调光直接失效**！
- **可用的值**：`100 nF`（τ = 0.55 µs）安全；`1 µF`（τ = 5.5 µs）推荐；`2.2 µF`（τ = 12 µs）勉强。
- ★ **判据：只有 `τ ≪ 开关周期` 才加电容。**

⚠️ **"IC 电源脚必须就近去耦"与"斩波负载不要并大电容"是两条方向相反的规则，不能一句话套用。**
而斩波负载真正该做的是**把电流回路走短**（减小环路面积），不是并电容。

### 3.3 ★★ 竖直细密条纹的定性过程（光学/感知）

**四条实测特征（全部来自用户目视）**：
1. **随背光亮度单调变化** —— 调到 60% 以下几乎看不见
2. **斜视时不动** —— 固定位置、竖直、均匀分布（排除摩尔纹/视角效应）
3. **黑底看不到** —— 对比度低就看不见
4. **与电源电容无关**（见 §3.2 #5）

**⇒ 定性：白底高亮度下暴露的背光/导光板光学不均（网点、扩散不均）。**
白底（0xFFFF）把 1 个 LSB 的亮度差放大到可见；黑底（0x0000）则看不出。

⚠️ **它不是屏的"个体缺陷"** —— 是**这块型号/这类背光结构的共性光学特征**，同型号换一块也大概率一样（而且被测的**就是** V2 要用的那块屏，没有"换一块试试"这个选项）。
**⇒ 正确处理 = 接受它 + 按需降默认亮度**，不要为它改电路、也不要换屏。

**★ 判据（下次遇到先做这两步）**：
- **① 降亮度** → 消失 ⇒ 光学
- **② 换底色** → 消失 ⇒ 光学/对比度，仍不消失才去查渲染/时序

### 3.4 ★★★ 整屏闪 = WiFi 电流脉冲（V2 必须处理的硬件问题）

**实测证据**：
- 日志 `wifi:dp: 1, bi: 102400, li: 3` ⇒ **beacon 间隔 102.4 ms ≈ 9.8 Hz**
- **关掉 WiFi ⇒ 屏幕边缘闪立即消失**（可复现）
- 开着 WiFi ⇒ 屏四周快速闪一下、黑条纹也加重，且**在"重/轻"两态间来回变**

**机理**：WiFi 每 102.4 ms 醒来收 beacon，瞬时抽 ~300 mA 脉冲
⇒ **3V3 轨跌落** ⇒ 屏 VCC 与 SPI 电平同时受扰 ⇒ 屏边缘（紧邻 LED、未经导光板充分漫射）最明显。

**★★ V2 的修法（按性价比排序）**：
1. ★ **模组 3V3 脚旁加 10~100 µF 陶瓷/聚合物体电容** —— 吸收 WiFi 脉冲，最有效。
2. 软件侧削 WiFi 峰值（若还要调）：`STATIC_RX_BUFFER_NUM` 32→8、
   `DYNAMIC_RX_BUFFER_NUM` 32→8、开 `CONFIG_ESP_WIFI_PS_MIN_MODEM`。
3. ⚠️ **不要在 SPI 线上并电容**（推挽信号会被压平边沿）。
   要抗扰只能**源端串 22~33 Ω**（V2_PLAN §10.6.8 已预留 0Ω/33Ω 0805 DNP 焊盘）。

**★★ 2026-10-14 复核修正 + 待做实验**（修正上文「修法排序」：体电容是**辅助**、主项是电源响应；且「最有效」从未在试板做过对照 —— 原为推断）

| # | 实验 | 目的 / 判据 | 做法 |
|---|---|---|---|
| **A** | **测 3V3 波形**（WiFi 开 vs 关）| 拿到缺失的核心数据：跌落**深度 × 宽度** | 示波器 AC 耦合 10~50 mV/div，分别探 ①屏 VCC ②模组 3V3 脚；无示波器 ⇒ 万用表 mV / AC 档对比开关 WiFi 的读数差（定性）|
| **B** | **加 / 不加体电容对照**：模组旁飞线并 **100 µF + 0.1 µF**（走线尽量短）| 检验「体电容到底管多少」= V2 主项之一 | 对比 A 的波形深度 + 屏闪变化 |
| **C** | **背光独立供电对照**：背光正极从板载 3V3 割开、改接**独立 3.3 V**（可调电源 / 第二路 LDO 模块），**注意共地** | **裁决 V2 要不要加「背光独立 LDO」**（`V2_PLAN §3.9.1` 新增候选）| 闪消失 / 大减 ⇒ V2 加 LDO；无变化 ⇒ 闪与背光无关（转查屏逻辑 / SPI 路径）|

- 三个都做完 ⇒ 一次把「V2 电源抗闪设计」定稿（不用等 V2 板）。
- ★ 排序修正：**① 电源响应（V2 的 `buck`，已天然拥有）② 近端 100 µF 体电容（辅助）③ 背光独立 LDO（候选强方案）④ 软件挪频率（备选）**。

### 3.5 ★ LVGL 使用坑（软件侧，V2 固件会复用）

1. **`lv_obj_get_coords()` 不触发布局** —— 只是 `*coords = obj->coords;`。
   **必须先 `lv_obj_update_layout()`**，否则恒返回 `x[0,-1]`（无效值）。
   （本次连踩两版才查到。）
2. **不要手动 `lv_obj_invalidate_area()` 去"修"移动的半透明对象** —— 本次实测：
   - 漏画 5px ⇒ 残留
   - 把区域扩大 5px ⇒ **残留反而扩大**
   ⇒ 说明问题不在"漏画"，手动干预无效且有害。**回到原生行为才对。**
3. **`lv_obj_set_pos()` + `lv_obj_align()` 混用**要注意：align 依据当前尺寸计算。
4. 移动 **半透明（`bg_opa`）+ border + radius** 的对象时，留意失效区域边界。
5. **`lv_span`/label 的框 = `line_height`**，不等于字形高度。本次实测的字体度量：

| 字体 | `line_height` | `base_line` |
|---|---|---|
| montserrat_14 | 16 | 3 |
| font_cn18（simhei 18px 子集）| 20 | 3 |
| montserrat_18 | 21 | 4 |
| montserrat_48 | 52 | 9 |
