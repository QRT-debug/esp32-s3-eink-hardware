# AI 语音终端可行性（ESP32-S3 做前端 · PC 跑模型）

> 2026-10-19 立。**用途**：评估「PC 本地部署语音模型 + ESP32-S3 做麦克风/喇叭终端」这条路线，本板需要补什么。
> 结论先行：**ESP32-S3 不做 AI，只做音频 I/O + 网络**；本板缺**麦克风**且 **IO 余量为 0**。

---

## 1. 分工边界（先划清楚）

| 环节 | 跑在哪 | 依据 |
|---|---|---|
| 唤醒词（"Hi ESP"） | **ESP32-S3 本地** | ESP-SR WakeNet9：PSRAM 324 KB + 内部 RAM 16 KB，每帧 3.0 ms / 帧长 32 ms ⇒ CPU ≈9% |
| AEC / NS / VAD（音频前端） | **ESP32-S3 本地** | ESP-SR AFE（MR, SR, LOW_COST）：内部 RAM 60 KB + PSRAM 740 KB，CPU 8.8% |
| ASR（语音转文字） | **PC** | Whisper 级模型几千万~亿级参数，S3 跑不动（Flash 16 MB / PSRAM 8 MB 差 2~3 个数量级） |
| LLM（对话） | **PC** | 同上 |
| TTS（文字转语音） | **PC** | ESP-SR 自带 TTS 仅 2.2 MB Flash / 20 KB RAM，但音质是机械音，不适合对话 |

**判据**：ESP32-S3 的价值 = 低延迟音频采集/播放 + 唤醒词 + 网络；**任何"通用语音理解"都不该放在它上面**。

## 2. 主控必须具备的能力（清单）

### 2.1 必须

| # | 能力 | 指标 | 本板现状 |
|---|---|---|---|
| 1 | **I2S 输入**（麦克风） | 16 kHz / 16 bit / 单声道，I2S 或 PDM | ❌ **无麦克风** |
| 2 | **I2S 输出**（喇叭） | 16~48 kHz / 16 bit | ✅ `PCM5102A`（`GPIO47`/`38`/`48`）|
| 3 | **WiFi 2.4 GHz** | 局域网 WebSocket 长连接 | ✅ 模组内置 |
| 4 | **PSRAM** | ≥ 2 MB（AFE 0.74 MB + WakeNet 0.32 MB + 音频/网络缓冲）| ✅ 8 MB |
| 5 | **Flash** | ≥ 4 MB（固件 + 唤醒词模型 0.37 MB + 双 OTA 分区）| ✅ 16 MB |
| 6 | **双核 240 MHz** | 一核跑音频，一核跑网络 | ✅ |
| 7 | **可用的 1~2 个 GPIO** | I2S DIN（复用 BCLK/WS 时只要 1 个）| ❌ **余量 0** |

### 2.2 加分（不强求）

| 能力 | 说明 |
|---|---|
| **AEC 参考信号** | 软件参考即可：把要播放的 PCM 直接喂给 AEC（不需额外硬件）；硬件回采更准但要一路 ADC |
| **VAD（端点检测）** | 决定"说完了没有"，影响上行包大小与延迟；ESP-SR 自带 |
| **本地命令词（MultiNet）** | 免联网的"开灯/调音量"；MultiNet7 要 PSRAM 2.9 MB，本板够但非必需 |
| **回声消除后的双工** | 要"边说边听"才需要；单问单答可省 |

### 2.3 **不需要**（避免走弯路）

- 本地 ASR / LLM：算力差 2~3 个数量级，别试。
- 本地 TTS：音质不可接受，除非只要"报数"。
- 蓝牙麦克风（HFP）：本板 `EWM104` 的音频**只到功放、不进 ESP32**，走不通。

## 3. 本板差距与补法

### 3.1 差距

| 项 | 状态 |
|---|---|
| 麦克风 | **没有**（`U4` 的 `MIC` 脚悬空，且模拟音频链不接 ESP32）|
| IO 余量 | **0**（已用 31 / 留空 2 = `GPIO45`/`46` / 不可用 3 = `35~37` PSRAM）|

### 3.2 三个方案

| 方案 | 需要几个脚 | 音质 | 说明 |
|---|---|---|---|
| **A. I2S 全双工（推荐）** | **1 个** | 好（SNR 60~65 dB）| 复用 `PCM5102A` 的 `BCLK`(`GPIO47`)/`LRCK`(`GPIO48`)，只加 **DIN**；ESP32-S3 官方支持 TX/RX 共享 BCLK/WS（FAQ 原文："在 duplex 模式下，TX 和 RX 就是通过将这两个信号绑定到同一引脚来实现"）|
| B. PDM 麦克风 | 2 个（CLK + DATA）| 好 | 抗干扰强、成本低（如 `SPH0641LU4H`）；但 PDM **不支持全双工**（TX/RX 时钟不同），喇叭要另占一个控制器 |
| C. 模拟麦克风 + ADC | 1 个（ADC1）| 差 | ESP32-S3 ADC 的 SNR ≈50 dB，只够近场命令词，不建议 |

**方案 A 的引脚从哪来**（三选一）：

1. **`GPIO46`**（留空脚）—— 但它同时是 **strapping**（ROM log 控制，上电需为低）。麦克风 `SD` 在无时钟时是三态，只要**麦克风供电晚于 strapping 采样**（RC 延迟或从 `3V3` 取电）就不会拉高。**能用但要写进设计注意。**
2. **`GPIO45`**（留空脚）—— strapping 更敏感（`VDD_SPI` 电压选择，上电必须低），**不推荐**。
3. **腾一个功能脚**（最干净）：把 `SW3`(`GPIO7`) 合并到编码器按压 `GPIO6`，腾出 `GPIO7` 给麦克风 `DIN`。代价 = 少一个独立按键。

### 3.3 麦克风选型（I2S，3.3 V）

| 型号 | SNR | 备注 |
|---|---|---|
| **INMP441** | 61 dB | 模块化最便宜（¥3~5），资料最多 |
| **ICS-43434** | 65 dB | 性能更好，贴片 |
| **MSM261S4030H0R** | 60 dB | 国产，便宜 |

## 4. 带宽与延迟预算（局域网）

| 项 | 数值 |
|---|---|
| 上行 PCM | 16 kHz × 16 bit = **32 KB/s = 256 kbps** |
| 下行 TTS PCM | 同量级（24 kHz 则 48 KB/s）|
| WiFi 实际吞吐 | 10~20 Mbps ⇒ **占用 <1%** |
| 采集 + VAD 端点 | 20~100 ms |
| 网络往返（局域网） | 20~100 ms |
| ASR（faster-whisper base） | 200~500 ms |
| LLM 首 token（7B 本地） | 300~800 ms |
| TTS 首包 | 100~300 ms |
| **合计（首字出声）** | **≈0.8~2 s** |

> 判据：**端到端 < 1 s 才"自然"**。想压到 1 s 内，必须做**流式 ASR + 流式 TTS**（分句送、边生成边播），不能等整段合成。

## 5. PC 侧需要的组件

| 环节 | 推荐 | 备注 |
|---|---|---|
| ASR | `faster-whisper`（base/small）或 `sherpa-onnx` | 流式用 `sherpa` 更顺 |
| LLM | Ollama（`qwen2.5:7b` 级）| 首 token 受显存/量化影响大 |
| TTS | `CosyVoice` / `GPT-SoVITS` / `Edge-TTS` | 要流式输出 |
| 服务框架 | FastAPI + **WebSocket** | 单连接双向流；别用 HTTP 轮询 |
| 传输格式 | 裸 PCM（16 bit LE）或 Opus | PCM 简单、Opus 省带宽（S3 解码要占 CPU）|

---

## 6. 结论

1. **主控的能力门槛不高**：I2S 输入 + I2S 输出 + WiFi + ≥2 MB PSRAM + 1 个空闲 GPIO。ESP32-S3 全部满足。
2. **本板的唯一硬缺口是麦克风**，且 IO 余量为 0 —— 加麦克风必须动一处（`GPIO46` 或腾 `SW3`）。
3. **软件上不需要写 AI**：只写「I2S 采集 → VAD/唤醒 → WebSocket 上行 → 下行 PCM → I2S 播放」这条管道。
4. 若只想验证可行性，**先用 `ESP32-S3-Korvo-2` / `BOX-3` 开发板**（自带双麦 + codec + AEC 参考），跑通再改自己的板。

## 7. 只播放模式（2026-10-19 追加 · 用户限定"只播放"）

> **需求收窄**：PC 侧做 TTS/生成语音，ESP32 **只负责接收 + 播放**，不做采集、不做唤醒。

### 7.1 结论：**本板硬件零改动**

| 能力 | 只播放时是否需要 | 本板 |
|---|---|---|
| WiFi 2.4 GHz | ✅ 必须 | ✅ 模组内置 |
| I2S 输出 | ✅ 必须 | ✅ `PCM5102A`（`GPIO47`=BCK / `48`=LRCK / `38`=DIN）|
| PSRAM | 建议 ≥512 KB（jitter buffer） | ✅ 8 MB |
| Flash | ≥4 MB | ✅ 16 MB |
| **麦克风 / I2S 输入** | ❌ **不需要** | — |
| **AEC / VAD / 唤醒词** | ❌ **不需要** | — |
| **额外 GPIO** | ❌ **不需要**（余量为 0 也无所谓） | — |

⇒ **不用腾 `SW3`、不用碰 `GPIO45/46`，板子原样就能用。**

### 7.2 现有播放链路（直接复用）

```
WiFi → ESP32-S3（WebSocket 收流）
     → I2S（GPIO47/48/38）
     → PCM5102A（XSMT=3V3 un-mute · SCK=GND 用内部 PLL · FMT=GND 标准 I2S）
     → U15 模拟开关（GPIO39 选到 PCM 侧）
     → NS4150C（BTL，5 V）
     → J7 → SQ201 喇叭
```

**唯一要确认的一件事**：`GPIO39` 的电平要选到 **PCM5102A 那一路**（另一路是蓝牙）。固件里固定该电平即可。

### 7.3 软件改动（很小）

| 项 | 原来 | 改成 |
|---|---|---|
| I2S 数据源 | SD 卡文件读（本地播放） | **WebSocket 收到的 PCM** |
| 缓冲 | 文件读缓冲 | 加 **jitter buffer 200~500 ms**（环形） |
| 任务划分 | — | 一核跑网络收包，一核跑 `i2s_channel_write()` |
| 断流处理 | — | 缓冲空 → 写静音；缓冲溢出 → 丢最旧 |

### 7.4 传输格式怎么选

| 格式 | 带宽（16 kHz 单声道） | ESP32 解码开销 | 判定 |
|---|---|---|---|
| **裸 PCM（16 bit LE）** | **32 KB/s** | **0** | ✅ **首选**（局域网带宽富裕）|
| Opus | ~4~8 KB/s | ~10~20% CPU + ~100 KB Flash | 带宽吃紧再上 |
| MP3 | ~4~8 KB/s | ~20~30% CPU（libmad） | 不推荐（解码费 CPU）|

若播放音乐（44.1 kHz / 16 bit / 立体声）⇒ 176 KB/s，WiFi 10~20 Mbps 仍然只占 ~1~2%。

### 7.5 延迟预算（只播放）

| 项 | 数值 |
|---|---|
| 网络单程（局域网） | 20~100 ms |
| jitter buffer | 200~500 ms（可调，越小越灵敏、越易断音）|
| I2S + DAC | <5 ms |
| **合计（收到包 → 出声）** | **≈0.25~0.6 s** |

> 注意：这**不含** PC 侧 TTS 生成时间。要做"低延迟对话"，TTS 必须**流式分句输出**，边生成边发。

### 7.6 一句话

**只播放这条路，ESP32-S3 属于"能力过剩"**：硬件不用动、IO 不用腾、不用写 AI；工作量全在 PC 侧的 TTS 流式服务和 ESP32 侧那条"收包 → 缓冲 → I2S"的管道。

## 8. 麦克风接入方案（删 `SW3` 腾 `GPIO7` · 2026-10-19 定）

> **用户决定**：不要 `SW3`（用户键 2），把 `GPIO7` 让给麦克风。

### 8.1 可行性：`GPIO7` 是干净的

活体核对（`GPIO7` 网只有 3 个成员）：

| 成员 | 说明 |
|---|---|
| `SW3.3` · `SW3.4` | 按键的两个脚（`SW3.1`/`SW3.2` → GND）|
| `U1.7` | ESP32-S3 模组的 GPIO7 |

**没有外部上拉、没有滤波电容**（原设计靠 ESP32 内部上拉）⇒ **删 `SW3` 即可，不需要清理任何外围**。删后 `GPIO7` 网只剩 `U1.7`，正好接麦克风 `DIN`。

`GPIO7` 是普通 IO：**无 strapping 功能**（这点比 `GPIO45`/`46` 好），支持 GPIO Matrix 任意映射到 I2S ⇒ 可用。

### 8.2 删除清单

| 删什么 | 位置 |
|---|---|
| `SW3`（`C318885`，`SW-SMD_4P-L5.1-W5.1-P3.70-LS6.5-TL_H5.0`）| @ (695, 980) |
| `GPIO7` 网上的连线（`SW3.3`/`SW3.4` → `U1.7`）| — |

> 删完 `GPIO7` 网只剩 `U1.7` 一个成员，属于"待接"，不是错误。

### 8.3 麦克风接线（I2S 全双工 · 只加 1 根新线）

| 脚（ICS-43434）| 名称 | 接到 | 说明 |
|---|---|---|---|
| **5** | `VDD` | **`3V3`** | 就近 **100 nF**（`C80`）去耦；datasheet 要求 |
| **3** | `GND` | `GND` | 地回流短，勿混功放/背光地 |
| **1** | `WS` | **`GPIO48`** | **与 `PCM5102A`（`U14.15`）共用同一根** |
| **4** | `SCK` | **`GPIO47`** | **与 `PCM5102A`（`U14.13`）共用同一根** |
| **6** | `SD` | **`GPIO7`** | **需 `R51` 100 kΩ 下拉到 GND**（datasheet 要求：三态时放电）|
| **2** | `L/R` | `GND` | 低 = 左声道（单声道用）|

**为什么只加一根线**：ESP32-S3 的 I2S 支持 **duplex**（TX/RX 共享 BCLK/WS），官方 FAQ 原文：「在 duplex 模式下，TX 和 RX 就是通过将这两个信号绑定到同一引脚来实现」。

### 8.4 ★ 硬约束：全双工必须同采样率

共享 BCLK/WS ⇒ **麦克风采集和喇叭播放的采样率必须相同**，不能一个 16 kHz、一个 44.1 kHz。

| 场景 | 采样率 | 处理 |
|---|---|---|
| **语音对话** | **16 kHz** | 采集 16 k + TTS 输出 16 k，最省 |
| **音乐播放** | 44.1 kHz | 麦克风也被配成 44.1 k（软件降采样到 16 k 再送 ASR），或**关掉麦克风** |

切换场景要 `i2s_channel_disable()` → 重配 → `i2s_channel_enable()`。

### 8.4b ★★ 共用时钟的软件坑：槽宽必须配 32 bit（否则麦克风不工作）

**电气上共用 BCLK/WS 是标准做法**（I2S 是"一个 master 广播时钟、多个从机同时接收"的总线，DAC 和麦克风都只是挂在总线上的从设备，各用各的数据线）。但**软件上有一个参数必须配对**：

`ICS-43434` 的 I2S 接口是 **24 bit 数据、每 WS 帧 64 个 SCK**（TDK 手册原文："24-bit, two's complement, **64 SCK cycles per WS stereo frame**"）。而 ESP32-S3 的 BCLK 由**槽宽**决定：

```
BCLK = fs × 声道数(2) × slot_bit_width
```

| `slot_bit_width` | BCLK（fs = 16 kHz）| ICS-43434 要求 64·fs | 结果 |
|---|---|---|---|
| 16 bit | 512 kHz（32·fs）| **1.024 MHz** | ❌ 时钟只有一半 ⇒ **麦克风不输出** |
| 24 bit | 768 kHz（48·fs）| **1.024 MHz** | ❌ 仍不对 |
| **32 bit** | **1.024 MHz（64·fs）** | **1.024 MHz** | ✅ **正确** |

**配置（ESP-IDF 5.x）**：

```c
i2s_std_config_t std_cfg = {
    .clk_cfg  = I2S_STD_CLK_DEFAULT_CONFIG(16000),
    .slot_cfg = I2S_STD_PHILIPS_SLOT_DEFAULT_CONFIG(
                    I2S_DATA_BIT_WIDTH_16BIT,      /* 有效数据 16 bit */
                    I2S_SLOT_MODE_STEREO),
    .gpio_cfg = {
        .mclk = I2S_GPIO_UNUSED,
        .bclk = GPIO_NUM_47,
        .ws   = GPIO_NUM_48,
        .dout = GPIO_NUM_38,   /* → PCM5102A DIN */
        .din  = GPIO_NUM_7,    /* ← ICS-43434 SD  */
    },
};
std_cfg.slot_cfg.slot_bit_width = I2S_SLOT_BIT_WIDTH_32BIT;   /* ★ 关键这一行 */
```

> 对 `PCM5102A` 无副作用：它支持 16/24/32 bit 槽，32 bit 槽下照常取有效数据。

**判据（首板必测）**：示波器量 `GPIO47`（BCLK），fs = 16 kHz 时必须是 **1.024 MHz**。量到 512 kHz 就是槽宽配错了。

---

**电气上还要注意两条（不是致命，但影响音质）**：

1. **驱动能力**：一个 GPIO 同时驱动 `PCM5102A` + `ICS-43434` 两个 CMOS 输入（各约 3 pF）——ESP32-S3 默认 20 mA 驱动，**绰绰有余**，不需要缓冲器。
2. **串扰**：`SCK`/`WS` 是方波，**走线必须远离模拟音频线**（`MIXLP`/`MIXSL`、`AMP_INP`/`AMP_INN`、`LINE_OUT`）。1 MHz 下没有传输线效应（10 cm 走线延迟约 0.6 ns，远小于 GPIO 上升时间），**不需要端接电阻**；但耦合到模拟线会直接变成可听噪声。

### 8.6 PCB 注意（画板时必须做）

1. **开声孔**：底部进音的 MEMS 麦克风要在 PCB 上开孔（Ø 0.5~1.0 mm），孔内**不能有铜和阻焊**；孔周围留出密封环。
2. **远离噪声源**：麦克风与 `BCLK`/`LRCK` 走线要避开 **背光 PWM（`GPIO15`/`Q3`）**、**buck（`U18`/`L4`）**、**功放（`U16`/`J7`）**。
3. **地**：麦克风下方铺完整地，去耦电容地回流要短。
4. **位置**：尽量靠板边，远离喇叭（否则 AEC 压力大、易啸叫）。

### 8.7 资源复核（ESP32-S3 @240 MHz）

| 项 | 占用 | 本板余量 |
|---|---|---|
| AFE（AEC/NS/VAD，MR+SR+LOW_COST）| RAM 60 KB + PSRAM 740 KB + CPU 8.8% | 8 MB PSRAM ✅ |
| WakeNet9（唤醒词）| RAM 16 KB + PSRAM 324 KB + CPU ≈9% | ✅ |
| **合计** | **PSRAM ≈1.1 MB · CPU ≈18%（单核）** | ✅ 充裕 |

### 8.8 代价

- **少一个独立按键**：`SW3` 原本承担"切歌"（`§3.12` 第 20 项）；原设计已把"切歌"并入编码器模式 ④，所以**功能上不丢**，只是少一个更顺手的入口。
- 板上多一颗麦克风 + 一个声孔 + 两根共享时钟线的分支。

## 9. ESP32-S3 原生 USB 的软件能力（2026-10-19）

> 本板 `GPIO19`/`20` 经 `U12`（USBLC6-2SC6）到 `J4`（Type-C）。ESP32-S3 的 USB 是 **OTG 1.1 全速（12 Mbps）**，不是高速 480 Mbps。

### 9.1 两套控制器，共用一对引脚（互斥）

| 控制器 | 用途 | 能否同时用 |
|---|---|---|
| **USB_SERIAL_JTAG** | CDC 串口（log/console）+ JTAG 调试 + `esptool` 下载 | ❌ 与 OTG **共用 GPIO19/20**，同一时间只能选一个 |
| **USB OTG 1.1 FS** | TinyUSB 设备/主机协议栈 | 同上 |

★ **这意味着：一旦固件跑 UAC/MSC 等 OTG 设备，USB 口就不再是"下载口+串口"**。本板有 `H2`（UART0 排针 `GPIO43/44`），烧录与日志改走 UART0 即可 —— 这是可接受的代价。

### 9.2 Device 模式能做的类（ESP-IDF / TinyUSB）

| 类 | 能做什么 | 对本板的意义 |
|---|---|---|
| **UAC**（USB Audio Class）| **把板子变成 USB 声卡**：扬声器 + 麦克风；支持音量/静音、ISO Feedback | ★★ **最有价值**（见 9.3）|
| CDC-ACM | 虚拟串口（可多个）| 调试、与 PC 传文本 |
| HID | 键盘/鼠标/自定义报告 | 编码器 → 音量旋钮（PC 直接识别为媒体键）|
| MSC | 把 **SD 卡暴露成 U 盘** | 传歌、导日志，不用拔卡 |
| MIDI | USB-MIDI 设备 | 用板子当 MIDI 控制器 |
| DFU | 通过 USB 刷固件 | 免按键升级 |
| Composite | 以上任意组合（如 UAC + CDC + MSC）| 一个口同时做声卡 + 串口 + U 盘 |

### 9.3 ★ UAC：比 WiFi 更优的"只播放"方案

官方组件 **`esp_device_uac`**（esp-iot-solution，基于 TinyUSB），示例 `usb/device/usb_uac`：支持 **最多 8 路扬声器 / 4 路麦克风**、可配采样率、音量/静音回调。

| 对比 | **USB UAC** | WiFi + WebSocket |
|---|---|---|
| PC 侧要装什么 | **什么都不用装**（系统自带 USB 音频驱动）| 要跑服务、配 IP |
| 延迟 | **10~20 ms**（USB Audio 典型）| 250~600 ms（含 jitter buffer）|
| 带宽 | 12 Mbps 全速，48 kHz/16 bit/2ch = 1.54 Mbps（占 13%）| 32~176 KB/s，WiFi 更富裕 |
| 稳定性 | 有线，不受路由器影响 | 受 WiFi 干扰（本板还有蓝牙共存）|
| 距离 | 线长限制（<2 m）| 局域网任意距离 |
| 调试口 | **失去 USB 下载/串口**（改用 UART0）| 保留 |

**结论**：**桌面场景（板子放电脑旁）优先用 UAC；要离开电脑用才需要 WiFi。**

### 9.4 本板的硬件限制

| 项 | 现状 | 影响 |
|---|---|---|
| USB 口方向 | `J4` 的 VBUS 是**输入**（从 PC 取电）| **不能做 USB Host**（接 U 盘/键盘/USB 麦克风），除非改硬件加 VBUS 输出开关 |
| 数据线保护 | `U12` 流过式 + `D7` VBUS TVS | 已是 device 口的标准配置 ✔ |
| 下载/调试 | 用 UAC 后须改 **UART0（`H2`：`GPIO43/44`）** | 排针已在板上 ✔ |

### 9.5 落地建议（只播放场景）

```
PC（任意播放器 / TTS）→ USB → ESP32-S3（UAC 设备）
   → I2S（GPIO47/48/38）→ PCM5102A → U15 → NS4150C → J7 喇叭
```

- 固件：`esp_device_uac` + `uac_device_output_cb` 里把数据写进 I2S；
- ★ **槽宽仍要 32 bit**（见 §8.4b），否则 I2S 时钟不对；
- 音量/静音：用 UAC 回调直接控 `GPIO41`（功放使能）或软件增益；
- 想同时保留调试，用 **Composite（UAC + CDC）**。

#### C. ★ 重要更正：ESP32-S3 **支持** PDM RX

之前本文档写过「PDM 麦克风本板不能用」，**这个说法不准确，现更正**：

- ESP-IDF 官方（`esp32s3/api-reference/peripherals/i2s.html`）写明：**ESP32-S3 supports PDM-to-PCM converter on I2S0**；中文文档补充「PDM RX 模式最多支持四条数据线……最多可以支持八个 PDM MIC」。
- 所以 **PDM 是技术上可行的**，只是代价比 I2S 高：

| | **I2S 麦克风**（当前方案）| **PDM 麦克风** |
|---|---|---|
| 占用 IO | **1 个**（DATA；BCLK/WS 与 PCM5102A 共用）| **2 个**（CLK + DATA）|
| 控制器 | I2S0 或 I2S1 全双工 | RX 必须 I2S0；TX 只能用 I2S1（**时钟不能共享**）|
| CPU | 无额外开销 | PDM→PCM 抽取滤波有开销 |
| 布线 | 3 线（含共享时钟）| 2 线但 CLK 是 MHz 级方波，更易串扰 |

**本板 IO 余量 = 0，只腾出了 `GPIO7` 一个脚** ⇒ 用 PDM 还要再砍一个功能。**所以结论没变（仍选 I2S），但理由是"多占 1 个 IO"，不是"接不上"。**
