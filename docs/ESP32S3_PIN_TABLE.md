# ESP32-S3 引脚功能速查表（本项目「看得懂版」）

> **用途**：本项目 V2 板主控 = **`ESP32-S3-WROOM-1-N16R8`**（立创 `C2913202` · 乐鑫）。
> 本文件把官方**分散在 4 张表里**的信息，合并成**按引脚组织、一眼看得懂**的形式，并标注本板用途。
> **数据来源（均为一手）**：ESP32-S3 数据手册 **Table 3-1 / 2-3 / 2-4** + **本机 ESP-IDF v5.5.5 源码**（`io_mux_reg.h` / `gpio_sig_map.h`）。
> 生成：2026-10-11

## 0. 先说清：为什么 ESP32-S3 没有"STM32 那样的引脚表"

**不是文档写得差，是架构不同。**

| | **STM32** | **ESP32-S3** |
|---|---|---|
| 复用机制 | **固定 AF 列表**（AF0~AF15）：每个外设只能接**指定的几个脚** | **GPIO Matrix**：外设信号可**路由到几乎任意脚** |
| 表的形态 | **引脚 → 功能清单**（一张表看全，很"满"）| **IO_MUX 表**（只列默认功能）+ **矩阵信号表**（信号 → 索引）|
| 结果 | 表里列满 AF | ★ **表里几乎是空的** —— 因为**功能不属于引脚** |

**官方原话**（ESP32-S3 数据手册）：

> 「Some are routed via the **GPIO Matrix** … **It gives the pin access to almost any peripheral signals.**」

**一句话**：**STM32 是"功能找引脚"，ESP32 是"引脚找功能"**。
⇒ STM32 能给出"这个脚能做什么"的清单；ESP32 **给不出** —— 真给出来，答案也是"几乎都能"。

**★ 用本机源码实证这一点**（`io_mux_reg.h`）：26 个有 IO_MUX 定义的 GPIO 中，**只有 15 个有"非 GPIO"的原生功能**，而这 15 个里 **12 个是 SPI 相关**（`GPIO8~14`、`33~38` 的 FSPI/SUBSPI），**只有 `GPIO19` / `20` 是 UART 相关**（`U1RTS` / `U1CTS`）。
⇒ **绝大多数脚的"原生功能"就是"GPIO"三个字而已** —— 这就是你觉得"表里没东西"的真正原因。

## 1. ★ 阅读方法：先记规则，再看表

### 1.1 通用规则 —— 默认"几乎都能"

下面这些外设，**可以接到几乎任意 GPIO**（走 GPIO Matrix）：

> **UART · I2C · I2S · SPI2 / SPI3 · LEDC(PWM) · RMT · TWAI(CAN) · 脉冲计数 · SD/MMC**

⇒ **你不需要查"这个脚能不能做 I2C"** —— 答案是**能**。**要查的只有下面的"例外"。**

### 1.2 例外 —— 这几类**必须**用固定脚（换不了）

| 类别 | 必须用哪些脚 |
|---|---|
| **ADC1** | `GPIO1~10`（CH0~CH9）|
| **ADC2** | `GPIO11~20`（CH0~CH9）⚠️ **与 WiFi 冲突** |
| **触摸（TOUCH）** | `GPIO1~14` |
| **USB** | `GPIO19`(D-) / `GPIO20`(D+) |
| **JTAG** | `GPIO39~42` |
| **外部 32 kHz 晶振** | `GPIO15`(P) / `GPIO16`(N) |
| **strapping** | `GPIO0` / `3` / `45` / `46` |
| **flash / PSRAM（模组内部）** | `GPIO26~32` + `GPIO33~37` |

### 1.3 第三类："有原生功能，但换脚也能用"

如 `GPIO9~14` 的 **FSPI**、`GPIO19/20` 的 `U1RTS/U1CTS`、`GPIO43/44` 的 `U0TXD/U0RXD`。

- **走原生（IO_MUX）的好处**：少绕一级矩阵 ⇒ **延迟更低**
- **高速 SPI 必须走原生** —— 走矩阵会被限到 **80 MHz**（本项目 SPI 正好落在 `GPIO9~14` 的 FSPI 上 ✅）

## 3. 官方那几张表分别在哪（以后自己查）

| 想查什么 | 看哪张 |
|---|---|
| 模组每个脚叫什么、**默认**功能 | **数据手册 Table 3-1「Pin Definitions」** ← ★ **大多数网络教程只贴这张** |
| 哪些信号走 IO_MUX（不走矩阵）| **数据手册 Table 2-3「Peripheral Signals Routed via IO MUX」** |
| **各脚的 IO_MUX 功能**（= "原生功能表"）| **数据手册 Table 2-4「IO MUX Functions」** ← ★ **这张才是你要找的那张** |
| 矩阵能接哪些信号 | **技术参考手册 第 6 章**「IO MUX and GPIO Matrix」**Table 6-1 / 6-2** |

> **你的困惑大概率来自：只看了 Table 3-1。** 那张**只列默认功能**，所以对 ESP32-S3 来说显得很空 —— 官方把"能做什么"放在了 TRM 的矩阵表里，而且那张表是**按信号组织**的（不是按引脚）。

## 4. 在本机 SDK 里自查（最准，不用翻 PDF）

ESP-IDF 就装在 `D:\Espressif\frameworks\esp-idf-v5.5.5`：

```bash
# ① 某个脚有哪些 IO_MUX 固定功能（例：GPIO3）
grep "FUNC_GPIO3_" \
  components/soc/esp32s3/register/soc/io_mux_reg.h
#   ⇒ GPIO3 只有 FUNC_GPIO3_GPIO3 / FUNC_GPIO3_GPIO3_0 两条 = 纯 GPIO
#   （对照 GPIO33 有 SPIIO4/SUBSPIHD/FSPIHD/GPIO33 四条）

# ② 某个外设的信号是否存在（例：UART1 的 RX）
grep "U1RXD\|U1TXD" \
  components/soc/esp32s3/include/soc/gpio_sig_map.h
#   ⇒ U1RXD_IN_IDX = 15 ⇒ 可过矩阵 ⇒ 任意脚可用
```

**★ 一句话**：**"某脚能不能做某外设"** → 先看 §1.1（能过矩阵的默认都能）；**"为什么表里没有"** → 因为功能在矩阵里，不在脚上。

## 5. 本板分配回看（结论）

| 项 | 结论 |
|---|---|
| **可用引脚池** | 模组引出 33 个 GPIO（`0~21` + `35~48`），其中 **`35/36/37` 被 PSRAM 占用不可用** |
| **交互 + 显示 + 音频 + 存储 全部占用** | **余量 = 0 个普通脚**（只剩 `GPIO45` / `46` 两个 strapping，且都不宜用）|
| **唯一"必须靠原生通道"的需求** | **3 路 ADC**（`GPIO1`/`2`/`8`，ADC1_CH0/CH1/CH7）—— **ADC 不能过矩阵**，这是全表唯一的硬约束 |
| **SPI 的运气** | `GPIO9~14` 正好是 **FSPI 的 IO_MUX 原生脚** ⇒ 不受"矩阵路由 80 MHz"限制 |
